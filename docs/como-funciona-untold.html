How UNTOLD works

The tools behind untold.ink, explained like a restaurant: one place writes the recipes, one serves the guests, and one keeps the pantry.

where the site is built where it lives and runs the people who read it

Each piece, in more detail

Read left to right in the diagram, then top to bottom here.

Claude Code

The chef who writes the recipes

What it is

An AI assistant that works on your computer, inside the project folder. You talk to it in plain language. It reads the files, changes the code, runs scripts and checks its own work before telling you it is done.

In UNTOLD

It built the features you see (the editor, topics, courses, the carousel pills) and does the hand translations and the article drafts from documents. Anything it changes stays on your computer until you ask for a commit. Its content scripts talk straight to Supabase, which is why a translation can go live at once.

GitHub

The recipe book and its inspector

What it is

A website that stores all the code and the history of every change, like version history in Google Docs. Any earlier version can be brought back, and nothing is lost by mistake.

In UNTOLD

Each saved change (a commit) goes to the main copy. Automated checks then run on it, and if one fails, GitHub emails you. GitHub holds no articles and no passwords, only the code.

Vercel

The dining room, open to the public

What it is

The company that hosts the site. It is the computer on the internet that answers when someone types untold.ink, so you do not have to run a server yourself.

In UNTOLD

Whenever new code arrives on GitHub, Vercel builds it and puts it online within minutes. It also runs a daily scheduled task (the profile reminders) and keeps the secret keys that connect the site to the other services, in its settings.

Supabase

The pantry

What it is

A database, a login system and a file store in one. Code says how to cook, but the ingredients are kept here.

In UNTOLD

Every article and its translations, the authors, topics, courses, user accounts and roles (admin, editor), and the uploaded images. When you save in the editor, it goes straight here, so no new release is needed. Your local test site and the live site share this one database, so a change made locally can change real content.

Readers

The guests

What happens

A reader opens an address. Vercel builds the page, asks Supabase for the article, and sends it back to their browser, usually in under a second.

Language in the address

No prefix means English. /es, /pt and /fr mean Spanish, Portuguese and French. If a translation does not exist yet, the page tries to create one automatically.

DeepL

An automatic translator

What it is

A translation service the site can call. It is fast but literal, and it often misses tone and the terms UNTOLD prefers.

In UNTOLD

Its free quota is used up, so translations are done by hand instead. While an article has no translation, the page still tries DeepL and shows "Traduciendo…". Switching that attempt off is an open option.

Gemini

An AI helper inside the editor

What it is

Google's AI model. The site connects to it with a key stored in Vercel and in .env.local on your computer.

In UNTOLD

It powers the AI features of the article editor, such as suggesting or rewriting text while someone writes.

Two things worth remembering

  • Code and content travel by different roads. Code goes Claude Code → GitHub → Vercel. Articles go editor → Supabase and appear at once.
  • The keys that join these services live in .env.local on your computer and in Vercel's settings. They are never saved in GitHub.
